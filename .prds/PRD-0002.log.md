  - `defueled` is a transition (T-006): a bare "DEFUELED" day continues the outage it sits in.

## T-008 -- 2026-11-14

`downpower_ingest::ledger` builds one row per in-service unit-day, streaming day by day from the
first status page to the last day either source covers. It keeps one page, the previous page's
rows and each unit's `Attributor` in memory. Over the archive it builds 1,020,802 rows in 29.5 s at
93 MB peak, with no unknown unit or tag, and `cargo xtask summary` now runs on it.

- **What a day gets.** Each in-service unit on the page, observed and attributed. A row inside the
  28-day hold is `reason_pending`. An in-service unit the NRC didn't report that EIA did is
  `no_report`, with EIA's power: 590 rows. Rows after a unit's shutdown are dropped. Rows come out
  ordered by docket.
- **Three new methods.** `reason_pending`, `no_report` and `unknown_tag` join `attribution::Method`,
  so every Unattributed row says why.
- **`source` is `nrc_page` or `eia`,** and `eia_power` carries EIA's value wherever it reports the
  same day. That replaces the PRD's three-valued `nrc_page+eia`, and the disagreement rate becomes
  a count over `eia_power`. NRC and EIA now disagree on 4 of 714,873 unit-days, since the 2013-07-19
  repeats no longer count.
- **Duplicates.** Copies that differ only in the change mark merge, keeping any mark. Otherwise the
  copy identical to the unit's row on the previous published page drops out, and a day where that
  doesn't leave one report fails. The archive has 107 such units (5 on 2006-06-22, 102 on
  2013-07-19), and all of them resolve.
- **Unknowns.** `Unknowns::Fail` (the backfill, an operator's rebuild, `cargo xtask summary`)
  stops on an unknown unit or tag. `Unknowns::Quarantine` (the server) attributes a row with an
  unknown tag as `unknown_tag` with the tags as evidence, skips a row naming an unknown unit, and
  counts both. The server's background rebuild runs unattended after a deploy, so it quarantines;
  Decision 21 is revised to say so.
- **`derived_version`** is 16 hex digits of sha256 over `LEDGER_VERSION` and the three catalog
  files, each length-prefixed.

`downpower_server::ledger` stores each build in its own table, `unit_day_<µs since epoch>`, one
record per unit-day keyed `[docket, date]`. `ledger:current` names the table and records the
version and the build summary. A rebuild drops any table a crashed build left (never the one
serving), writes the new table in 5,000-row `INSERT`s fed through a two-batch channel from the
builder on a blocking thread, then swaps `ledger:current` and the `unit` table in one
transaction, and drops the old table. `serve` calls `ensure_current`, which rebuilds in the
background when the version differs, so the previous build keeps serving until the swap.

Measurements, release builds on the home box (128 cores), with the 64 MiB caps:

| Operation, 1.02M rows | Time | Peak RSS |
|---|---|---|
| `INSERT` in 5,000-row batches (synthetic rows) | 20 s | 195 MB |
| `SELECT` every row | 1.1 s | 1.17 GB |
| `DELETE` the table's rows in one statement | 22 s | 2.1 GB |
| `REMOVE TABLE` | 2.8 s | 896 MB |
| `DELETE` one unit's id range at a time | 21 s | 253 MB |
| The real rebuild in `serve`, all 128 cores | 33 s | 522 MB |
| The same on 2 pinned CPUs, `MALLOC_ARENA_MAX=8` | 31 s | 292 MB |

- The 128-core run spends its extra memory on 262 threads and glibc's per-core arenas; a 1-CPU
  Fly machine gets one worker and eight arenas, like the pinned run.
- A build takes 282 MB on disk, so a volume briefly holds two during a rebuild.
- **For T-013:** the barcode endpoint must never select every row. Pack the buffer during the
  rebuild instead.
- **For T-011:** rows the daily job writes to the current table while a rebuild runs would be lost
  at the swap, so the daily job waits for a running rebuild.
- **Stacks.** SurrealDB overflows a 2 MiB stack in a debug build. `downpower_server::runtime()`
  gives every worker 8 MiB, the binary runs on it, and Surreal tests run through
  `tests::block_on`, which spawns onto it.
- Surreal 4 refuses to read a table that was never defined, so `db::open` defines `ledger` and
  `unit`. Build tables are `SCHEMALESS`, and the Rust `UnitDay` type is the schema: a test reads a
  unit's rows back and compares them with the builder's.
