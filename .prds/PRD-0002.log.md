## T-003 -- 2026-11-13

`downpower_ingest::status::parse` read every stored status page, the latest capture of each date, in
31 s (release build, decompression and hash checks included), with no errors.

- 10,145 pages carry all six columns, and 27 (2026-10-17 to 2026-11-12) are inside the 28-day hold
  with `Unit | Power` only. In all: 1,022,782 unit-days, 110 unit names, and 24,442 distinct reason
  strings.
- Seven read "No data available for this date." with no tables, under a 200. 2026-11-13 wasn't
  published yet. The other six (1999-05-08, 2013-07-18, 2013-12-21, 2015-12-02, 12-03 and 12-04)
  read the same on a second fetch a day later, so they are permanent gaps.
- Every page has exactly four region tables, in order. Power is always an integer from 0 to 100,
  `Down` is ISO or blank, `Change in Report (*)` is `*` or blank, and `Scrams (#)` is blank or `1`,
  first on 2013-06-29.
- 2006-06-22 lists five units twice: Vogtle 1, Vogtle 2 and Watts Bar 1 in Region 2, and
  Waterford 3 and Wolf Creek 1 in Region 4. The copies agree except that one Wolf Creek 1 row has
  the change mark. The parser keeps both, since it reports the page as written; the step that keys
  rows by docket (T-008) has to merge copies that agree and fail on copies that don't.
- Pages from 2025 on put a lone NUL in a blank reason cell. html5ever drops it inside a table cell,
  as the HTML spec says it must, so the parser needs no stripping; two tests pin that.
- Fixtures: eight pages (1999-01-05, 1999-05-08, 2008-07-15, 2013-06-29, 2016-07-15, 2025-07-15,
  2026-10-15, 2026-11-12) copied byte for byte from the raw store. `.gitattributes` marks them
  `-text`, so git never rewrites their CRLFs.
