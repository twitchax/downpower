# Summary
The site's view onto PRD-0003's event tables: a filterable list of every Event Notification since
1999 with a counts-per-month chart, a detail page per event, and event markers on the fleet barcode
that tie the two NRC sources together.

# Problem
After PRD-0003 the events are parsed and joined, but only `/status` and the resolved causes show
it. Nearly 20,000 events across eleven categories need a way in: by place, by facility, by 10 CFR
section, by text. On the barcode, a reader looking at an outage can't yet see the event that
explains it.

# Goals
1. `/events` answers "what was reported, where, and when" with every filter permalinked.
2. `/events/{number}` shows one event completely, updates and retraction included, and links back
   to the NRC.
3. Barcode markers show reactor events on their unit rows without burying the cause colors.
4. The barcode readout links each `See EN#` to its event.

# Technical Approach
- **State.** `EventsState` in `downpower-core` holds the filters (`from`, `to`, `category`,
  `state`, `facility`, `unit`, `cfr`, `class`, `scram`, `q`, `page`). It parses from and
  serializes to the query string as `ViewState` does, so the server renders the same page the
  browser hydrates. `ViewState` gains `events` for the markers.
- **API.** Three endpoints read the serving build: the list, the counts and one event. The counts
  come back as the stacked area's series type, so `area`'s geometry draws them unchanged.
- **Categories in the chart.** There are eleven category groups once the renamed pairs merge. By
  size: Power Reactor (about 9,800), Agreement State (4,203), General Information (2,334), Fuel
  Cycle (914), Other Nuclear Material (686), Non-Agreement State (622), Part 21 (492), Hospital
  (444), Research and Non-Power Reactor (152), ISFSI (29), Transportation (14). The chart shows the
  seven largest and folds the rest into Other.
- **Search.** The server keeps each event's lowercased title, text and names in memory per build
  (35 MB) and answers `q` by substring, every word required (T-001).
- **Markers.** A packed buffer of (unit row, day, kind) per mapped, unretracted reactor event,
  ETag-cached like the barcode's, drawn over the canvas only when `events` is on. Scrams get a
  distinct shape. Hit-testing reuses the barcode's pointer math.

# Assumptions
- PRD-0003's tables carry everything the views need: the update timeline, retraction, units with
  dockets, the facility or licensee group, and the resolution evidence.
- About 9,800 markers fit on the canvas without a level-of-detail scheme. Several events on one
  unit-day draw as one marker whose hover lists them all.

# Constraints
- No component or chart library (Decision 23, CLAUDE.md).
- The design language's tokens, without the grid. One filter row above the charts.
- The search text has to fit the 1 GB Fly VM alongside two builds during a swap: 35 MB each.

# Non-Goals (MVP)
- Fitness-for-duty views (PRD-0005).
- A page per facility or licensee; the filters cover it.
- Diffs between fetched versions of a page (Decision 30).
- Exporting results as CSV.
